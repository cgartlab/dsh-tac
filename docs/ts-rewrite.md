# TypeScript rewrite — complete

The plugin's source is TypeScript under `src/`; `client.js` and `index.js` are generated by
`scripts/build.mjs` (esbuild). The rewrite is finished: the built bundle is the shipped
artifact and passes the whole existing suite.

## Toolchain

- `tsconfig.json` — `strict`, target ES2022, `noEmit` (type checking only).
- `scripts/build.mjs` — bundles `src/index.ts` → `client.js` (IIFE) and `src/host-entry.ts`
  → `index.js` (ESM). The output is deterministic, so CI can assert the committed artifacts
  match the sources.
- `npm run typecheck` / `npm run build` / `npm run check` / `npm test`.

## Design decisions

- **No React import.** The host owns React; `src/runtime.ts` binds the loader's
  `require('react')` once and every module uses the live `h` / `useState` / … exports, so the
  bundle never has a top-level `require`.
- **No JSX.** Components keep the original `h()` call style, which keeps the diff against the
  legacy implementation reviewable and avoids a JSX factory configuration.
- **Data blocks lifted verbatim** (`i18n/`, `ui/icon-data.ts`, `styles.ts`) so the 240-key
  dictionaries and ~400 lines of CSS could not drift during the port. `en` is typed as
  `Record<keyof typeof zh, string>`, so key parity is a compile error.
- **Host contract in `src/host.ts`** — the harness publishes no declaration package for
  plugin authors, so the used client surface is declared explicitly and cast at the boundary.

## Verification

1. `npx tsc --noEmit` clean.
2. `npm run build` regenerates `client.js` + `index.js` deterministically.
3. `npm test` — the pre-existing suite passed against the built bundle at the time (13/13 back then; 141 tests as of this writing — the count keeps growing, so run `npm test` for the current number).
4. `npm run check` — typecheck, manifest/exports/syntax, i18n parity **and** a check that the
   built bundle embeds every dictionary key.
5. The plugin hot-reloads in the running GUI and logs `plugin ready`.
