# 录制演示视频前的检查清单

这份清单给"录一段视频介绍 dsh-tac"用：录制前 5 分钟做什么、每个镜头的预期结果、
以及哪些操作看起来像 bug 其实是宿主行为（录进去会很尴尬）。

## 一、录制前（5 分钟）

1. **应用必须是当前版本。** 重启 DSH（不是刷新窗口），然后在终端确认：

   ```powershell
   npm run version:report -- --gui=http://127.0.0.1:<当前端口>
   ```

   报告里 `running app (market API)` 那一行必须是 `installed 0.6.0`。若还是旧版本，
   窗口里加载的就是旧插件——归档、看板分组这些镜头会直接失效。
2. **准备数据**：至少 3 个会话、2 个项目；其中一个会话处于**空闲**状态（用于演示归档，
   运行中的会话归档会被宿主拒绝）。再准备一个可以随便删的临时会话。
3. **GitHub 列（可选）**：设置 → 行为/GitHub 里配好 owner/repo 才有数字，否则整列显示 `—`。
   不想展示就先把这几列在设置里关掉。
4. **通知**：如果要演通知，先在系统里给 DSH 开通知权限，并跑一个会完成的回合试一次。
5. **关掉命令面板的"只看已归档"等临时筛选**，避免下一个镜头从奇怪的状态开始。

## 二、镜头清单（按推荐顺序）

| # | 操作 | 预期结果 | 注意 |
| --- | --- | --- | --- |
| 1 | `Alt+N` | 右侧栏打开项目看板（窄 380px），再按一次关闭 | 任何尺寸键在"开着"时都是关闭 |
| 2 | `Alt+B` / `Alt+V` | 半屏 / 全屏打开看板；再按同一键关闭 | `Alt+W` 会先退出全屏再动侧栏 |
| 3 | 看板顶部切「会话」标签 | 会话表：项目/名称/状态/类型/预设/最近活动/打开 | 列头可点排序，`Shift`+点击叠加第二排序 |
| 4 | 会话表工具栏「分组」下拉 | 按项目/状态/类型/预设/更新时间分段/当前会话分组，组头可折叠、显示组数 | 选择会记住，重开面板还在 |
| 5 | `Alt+K` | 命令面板：搜索会话/项目/设置，`↑↓` 或 `Alt+I`/`Alt+,` 移动，`Enter` 打开 | 搜索框里打字时列表实时过滤 |
| 6 | 面板里点「只看已归档」chip | 列表只剩归档会话；每条右侧有「取消归档」 | 选中归档行时底部出现 `Shift+Enter` 提示 |
| 7 | 点「取消归档」或按 `Shift+Enter` | 会话当场恢复，提示条是**成功色**（不是橙色警告） | 连点不会发两次请求 |
| 8 | HUD 悬浮列表（`Alt+E` 收起/展开） | 运行中会话带计时，底部快捷键脚注完整 | 拖拽移动、贴边收起 |
| 9 | HUD 行悬停 → 归档按钮 | 闲置会话被归档，提示成功 | **运行中的会话**会被宿主拒绝并提示原因——这是设计行为 |
| 10 | 原生聊天区「回到底部」箭头 | 一次点击就滚到最底（0.5.2 修的问题） | 流式输出中点也稳定 |
| 11 | `Alt+S` | 回到底部并把焦点放回输入框 | 与原生箭头等效 |
| 12 | `Alt+U` / `Alt+M` 轻按 | 跳到上一条 / 下一条用户消息 | 按住是连续滚动 |
| 13 | `Alt+R` 重命名 | 对话框改名，回车保存 | 失败会留在对话框里并显示原因 |
| 14 | `Alt+D` 会话菜单 | 归档 / 删除（删除不可恢复，演示用临时会话） | 删除前会二次确认 |
| 15 | 设置页 | 各分区：快捷键录制、看板、HUD、GitHub、日志与排查 | 关掉的功能会把子设置变灰 |
| 16 | 切会话 | 看板的开合/尺寸保持不变 | 面板状态属于工作区，不随会话重置 |

## 三、容易被误当成 bug 的行为

- **归档运行中的会话会被拒绝**：宿主不允许归档正在跑的会话，插件会把宿主的原因用提示条显示。
  演归档请挑空闲会话，或先停止该会话。
- **GitHub 列为 `—`**：没有配置 owner/repo（或 token 无效/限流）时的正常占位，不是加载失败。
- **命令面板在有筛选时第一次 `Esc` 只清筛选**，第二次才关面板——这是预期。
- **删除会话不可恢复**，没有回收站；演示用可抛弃的会话。
- **`Alt+E` 在 HUD 已经收起时是展开**、展开时是收起（全局开关，不是逐会话）。
- **首次打开看板落在「项目」视图**：这是默认视图，可在设置里改。

## 四、录制后

- 顺手截三张图替换 `docs/screenshots/`：看板（含分组下拉）、命令面板（含「只看已归档」chip）、
  HUD。然后跑 `npm run check`，把 `screenshots.meta.json` 里的 `showsVersion` / `verifiedThrough`
  更新到当前版本与提交（详见 `docs/screenshots.md`）。
- 若录制中遇到没见过的异常，把「设置 → 日志与排查」里对应时间点的几行贴出来，按日志定位。

## 五、当前可靠性证据（本机实测）

- `npm run check` 通过，`npm test` **176/176** 通过（加载、14 个快捷键、看板、命令面板、
  HUD、设置、通知、GitHub、滚动、版本一致性）。
- 演示用的关键路径都有回归测试：排序/叠加排序、超过 200 条的分批 +「显示更多」、
  列可见性、分组与折叠、归档/取消归档、回到底部、命令面板键盘导航等。
- 发布产物与本地构建逐字节一致（`client.js` sha256 相同），装进 profile 的也是同一个文件。
